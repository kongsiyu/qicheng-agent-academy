# 课程质量设计与验收合同

设计基线：2026-11-17；默认交互于 2026-11-20 重构。本文是维护者的实施与评审依据；不是已经取得学习效果的证明。

追加修复：2026-11-20 完成旧路径逐步编辑改造，并纳入 2026-11-21 发布版本。此前仅默认入口的三步简化没有覆盖全部课程与恢复路径，本轮一并修正。

## 1. 课程承诺与边界

面向非技术岗位，主线承诺是：学员能选择一个合适的真实任务，准备资料，说明需求，使用现成 Agent 完成交付，核查关键结果，纠错，并判断这种方法是否值得复用。

课程采用 14 节主线加 3 节选修。前四周形成完整使用过程；第五、六周按需学习定制助手和自动化。JSON、API、Webhook、鉴权留在后续按需学习，模型训练等不进入本轮主线。

六个任务包为 meeting（会议待办）、research（竞品简报）、spreadsheet（表格分析）、knowledge（资料问答）、review（文稿初审）、weekly（项目周报）。学员选一个作为贯穿四周的主线，再选一个不同任务做迁移；不把浅做六种任务当作熟练。

每周约 3—4 小时是包括资料准备、外部执行、核查、修改和项目记录的安排。短课标注分钟数只能表示预计学习时长，不能表示实际投入或工作省时。

平台区分普通练习保存、课程理解题通过、正式项目证据齐全和学员自评达到独立水平。人工抽评通过另行记录；不能把其中任一种改称职业能力认证。

## 默认三步练习与正式验证分层

默认入口为 `#/project/start`；旧 `#/project/path` 兼容进入同一新手流程。学员在实验室只选任务，随后逐步看到资料、外部执行、对照检查；不先面对学习目标、练习类型和完整项目表单。

| 步骤 | 学员看到和做什么 | 默认主要文本输入 |
| --- | --- | --- |
| 1. 准备资料 | 直接阅读虚构示例即可继续；需要时换成自己的可用资料，保留来源、日期、版本和缺失信息 | 0 个；替换资料才输入 |
| 2. 让 Agent 帮忙 | 一次复制自动合并的资料与任务要求，去常用 Agent 执行，再粘贴实际输出 | 1 个：实际输出 |
| 3. 检查并保存 | 对照原文和输出逐项核查，不确定项保留未勾选；发现问题时可写一句问题或修改 | 0 个；问题备注选填 |

默认路径的主要文本输入为 0 / 1 / 0。资料和任务说明自动提供，唯一要求手动填写的主要文本是实际输出。全部自检尚未勾选也可保存；保存页如实展示未确认项，不将“保存成功”解释成“结果已正确”。

首次练习不安排前测、人工基线、八项评分、完整时间账或六项个人任务包。完整课程、示范与辨错、正式项目及旧自检记录继续保留；学员准备好后，可主动从 `#/project/plan` 进入完整计划。正式试学研究的前测由主持人主动安排，不能用默认轻量练习事后冒充学前独立表现。

普通练习使用 `kind: practice`，只允许 `support: guided`，保存快照时检查有效资料、已有任务说明和实际输出。校验不要求 `sourceCheck`、`correction`、`decision`、八项自评、耗时或全部检查项；正式类型按各自合同校验。这是实际的校验分层，不能只在界面折叠原有必填表单而继续阻止保存。

`practice` 不进入正式周项目、八项能力等级或延后复验计算，也不能因勾完清单升级为独立记录。改动资料或输出后清除自检，历史快照保留。来源和验收的教学动作仍在默认流程中，只是不要求新手为每个动作另写一段证明。

## 11 月 20 日追加：统一正式练习与旧草稿

用户的 research scaffold 截图精确复现了遗漏路径：课程半成品按钮仍会创建 `normal` 草稿并进入旧 `P.runView`，整页同时要求资料、说明、输出和多段证据。此前只对默认入口做三步简化，不能据此认为课程链路、刷新恢复或任务包带入已经全部简化。

本轮在本地删除旧长表单实现，使用 `project-runner.js` 为所有正式类型、冷启动旧草稿、课程 scaffold、周项目和任务包带入逐步呈现。每屏最多一个主要长文本框；日期、提示情况与资料性质在相应确认步骤处理。独立验证继续不提供教学任务说明，不因页面变短自动降低独立要求。

默认正式核查仅必填一条 `sourceCheck`，包含关键结论、资料依据和实际核查结果。`correction` 是发现错误后的选填修改记录；`decision` 仅在 `missing`、`conflict` 与 `automation-*` 类型必填，其他类型遇到缺口或权限动作时仍可记录。前测和人工基线保留原有专门规则。四项正式自检、迁移字段、选修实测、真实日期和时间账门槛继续生效，不将减少重复叙述变成放弃验收。

六项任务包内容仍按原合同保存，但一次只编辑一项；计划页默认只展示当前一步。旧 `#/task/:id` 由 `P.openLegacy` 适配逐步继续，原数据只读保留；导入旧任务、带入任务包前保护当前草稿，跨标签页同步保留编辑内容，备份恢复仍经明确确认。

维护检查新增 `node tests/project-runner.test.cjs` 与 `node tests/app-routing.test.cjs`，覆盖旧截图路径和恢复、导入、路由等实际到达方式。测试只说明实现行为，不是已发布状态或真实试学成效。

## 2. 八项能力、练习和证据矩阵

| 能力 | 学员必须练的动作 | 最少可核查证据 | 评审追问 |
| --- | --- | --- | --- |
| 1. 任务选择 | 比较日常任务，按重复性、输入、可检查性和复核成本选一个 | 所选任务、至少一个放弃的选择、选择理由与人工边界 | 这项工作哪一步交给人更合适？ |
| 2. 基本概念 | 对同一场景选择聊天、Agent 或固定工作流，辨认工具和知识资料的作用 | 一次场景选择及理由；后续项目中实际采用的方式 | 如果只需解释一段文字，为什么还要或不要执行工具？ |
| 3. 需求说明 | 独立写目标、背景、资料、限制、格式、验收六项说明 | 可编辑的个人任务说明和一次有原因的修订 | 换一个人接手，哪里还会产生歧义？ |
| 4. 资料与上下文 | 整理来源、版本、有效日期、范围和表格口径；发现缺失或冲突 | 资料清单；一处缺失或冲突的定位与处理 | 如何确认 Agent 读到了需要的页、列或条目？ |
| 5. 人机协作 | 拆分过程，在方向或影响扩大前设检查点，给具体反馈 | 一个检查点、一条反馈和调整后的结果 | 如果等最终结果才看，会多返工什么？ |
| 6. 工具和权限 | 区分搜索、读取、修改、写系统、发送；核对对象、范围和审核人 | 本次允许的动作、写入或发送前的确认位置；无写操作也要说明 | 它读了什么，改了什么，哪些动作还没有授权？ |
| 7. 验收与纠错 | 回到原始资料核查关键事实、引用、日期、计算和遗漏 | 至少一条关键核查的原文或计算依据；发现问题时保留修正 | 这条结论为什么可信？如果无法验证，应怎样交付？ |
| 8. 复用与收益 | 同法测试正常、缺失、冲突输入；维护任务包；比较完整耗时；迁移 | 多次运行记录、个人任务包、人工基线和 Agent 全过程时间、第二任务差异 | 换材料后是否仍有效？省时是否包含核查和返工？ |

矩阵用于完整项目与正式抽评，不是默认三步练习的必填表单。证据允许由同一个实际动作同时支持多项能力，不要求八份重复记录。平台可检查正式字段和记录之间的关系；证据是否成立需要自检和人工抽评。

## 3. 四周主线与提示逐步撤去

以下为 `#/project/plan` 的完整学习与验证安排。进入默认三步练习不强制同时承担整套周项目记录；普通练习可以为学习做准备，但不会自动满足正式项目门槛。

| 阶段 | 学员活动 | 提示程度 | 必交成果与检查 |
| --- | --- | --- | --- |
| 第 1 周 | 选主线任务；看完整示范；辨认一份含关键错误的结果；完成正常输入运行 | 示范可展开，先观察原文如何支持结果；再对自己的材料执行 | 选题理由、正常运行、关键来源或计算核查；不把示例观看计为独立成果 |
| 第 2 周 | 同一方法处理正常、缺字段、冲突材料；根据失败原因修订说明，再复查原案例 | 先给结构提示，再撤去完整任务说明；允许请求帮助并记录 | 三种输入各有实际输出和处理结果；修订后复查此前通过的案例 |
| 第 3 周 | 整理六项个人任务包；请另一人照着使用；根据反馈修改 | 使用者先不接受作者口头补充；卡住后记录求助再继续 | 选择理由、资料清单、任务说明、验收表、失败恢复、他人使用反馈与交接说明 |
| 第 4 周 | 主线独立交付；迁移到第二任务；记录真实工作使用和完整时间账 | 开始时不展示课程预置答案；学员可用自己的任务包、常用 Agent 和真实资料 | 主线独立运行、第二任务迁移、至少两次主线真实运行及实际日期、完整耗时和质量检查 |

第 4 周的两次主线真实运行应在不同实际日期，最早与最晚跨度至少 6 个自然日；日期采用 Asia/Shanghai。学习页面访问、课程答题或同日复制记录不能替代真实运行。

本轮独立交付不是闭卷考试。允许使用现成 Agent、个人任务包和工作资料；必须由学员完成任务选择、关键核查、边界判断与最终接收。课程提示或他人帮助介入时，记录帮助发生在哪一步，并按评分标准判断是否仍为独立。

主线独立运行实际日期至少 7 天后，在第二任务上提交一份新的延后复验。它单独呈现为后续验证，不能用未来日期提前填报，也不把刚完成第四周的学员直接描述成已经通过延后验证。

如果没有同事，主持人或另一位试学者可作为任务包使用者。作者自己扮演接手人可以练习，但不能替代真实的他人使用反馈。

## 4. 六项个人任务包合同

| 项目 | 保存什么 | 如何判断有用 |
| --- | --- | --- |
| choice：选择理由 | 用途、适用任务、不适合交给 Agent 的部分、预计复核负担 | 接手人知道何时使用和何时停止 |
| materials：资料清单 | 必备材料、来源、版本、有效日期、字段口径和最少背景 | 能在开始前发现缺失、过期、无法读取或相互矛盾 |
| instruction：任务说明 | 六项需求、可替换参数、未知信息规则和工具动作范围 | 换一批输入仍可明确执行，不沿用旧日期或旧结论 |
| rubric：验收表 | 关键事实、引用、计算、完整性和业务限制的具体检查动作 | 检查有参照物，不只写“专业、准确、完整” |
| recovery：失败恢复 | 已遇问题、原因、修订、原失败案例和回归检查方法 | 遇到同类问题有处理路径，不能无限重试或猜测补齐 |
| handoff：交接与反馈 | 操作步骤、输出示例、他人使用时卡住的位置和修改 | 他人无需作者现场补全关键规则即可完成任务 |

示例任务包是教学材料。个人任务包应可编辑、版本化并导出；修改重要规则后保留原测试输入，重新检查正常与异常案例。

## 5. 评分标准与锚例

每项能力采用三档评分。0 表示没有体现或做错且未识别；1 表示在课程提示或他人具体指出后完成；2 表示独立完成并能展示足够依据。评分依据是实际行为与作品，不能仅依据自述的熟练程度。

| 能力 | 0：未体现 | 1：提示后完成 | 2：独立完成 |
| --- | --- | --- | --- |
| 任务选择 | 目标含糊，无法检查或没有考虑复核 | 经追问缩小任务、补检查办法 | 自己选择可执行任务，解释收益与保留给人的判断 |
| 基本概念 | 混淆回答问题和修改系统 | 根据提示选对方式 | 依据场景决定聊天、执行工具或固定流程，并解释理由 |
| 需求说明 | 缺关键限制或交付要求 | 给六项模板后补齐 | 自己提出六项说明，接手人能照着执行 |
| 资料准备 | 混用版本、遗漏字段且未发现 | 经指出补资料或说明口径 | 开始前发现缺失、冲突或读取问题，并给处理路径 |
| 人机协作 | 方向已错仍持续执行 | 被提醒后补检查点 | 自己在关键处看中间产物，反馈具体并复查修正 |
| 工具权限 | 未确认目标或范围就接受修改、发送 | 被提醒后暂停并核查 | 自己区分动作影响，核对对象、范围和需要人工确认的步骤 |
| 验收纠错 | 看格式就接收，关键错误未识别 | 指出类别后找到并修正问题 | 自己核对关键依据，发现并修正错误，未知信息保持未知 |
| 复用收益 | 只保存成品，或只计生成时间 | 按提示补测试和时间账 | 自己维护任务包、验证新输入、记录完整成本并解释迁移调整 |

“提示后完成”包括主持人明确指出某一版本、某个数字或某条来源存在问题。一般性的任务规则说明和学员自行使用个人任务包，不自动视为提示。

以下锚例用于评审校准；正式后测须替换人物、数值、来源与表述，不能让学员背答案。

| 场景 | 合格行为锚例 | 关键错误锚例 |
| --- | --- | --- |
| 会议待办 | 原文未指派负责人，输出待确认；无会议日期时保留相对时间 | 自行指定负责人，或将“下周一”换成无依据的日历日期并接收 |
| 竞品简报 | 新旧价格并存，说明版本与当前可确认范围；打开依据检查是否支持结论 | 引用真实产品页，却写出页面没有的能力或价格，并把引用当作证明 |
| 表格分析 | 100 次访问 10 次报名，900 次访问 45 次报名，整体为 55/1000=5.5% | 直接平均两个比例得到 7.5%，并据此作关键判断 |
| 资料问答 | 发票政策未提供，回答未知并列确认对象 | 按行业惯例肯定承诺开票、退款或功能，资料并不支持 |
| 文稿初审 | 6/7 满意只描述已回复样本，保留样本限制 | 将样本满意率扩大为“所有客户认可”，未识别范围变化 |
| 自动化或写入 | 人工确认草稿、目标系统和字段后写入；失败时记录并停止 | 未授权即发送，写错记录，或失败后重复发送且无核查 |

未被识别和修复、足以改变业务判断或造成越权的事实、来源、计算、日期及权限错误属于关键错误。关键错误不能被排版、表达或其他能力的高分抵消。无依据的肯定结论，应按未知或需人工确认处理。

缺少足够证据时标为“待核查”，不按无错误自动判为合格；合理标注无法确认的信息本身不算错误。一般措辞、无业务影响的排版、约定范围内的四舍五入不与关键错误混为一类。

八项能力达到 2 是主线独立掌握的设计目标。界面可先显示“自评证据齐全”，抽评者核对后才记录人工评价；平台不以加总分制造能力认证。关键证据应能导出，便于课程外复核。

## 6. 选修交付与延后复验

第五周必须在学员选用的外部平台实际创建或配置助手，保存稳定指令、有效知识资料、输出规范及引用要求。至少运行正常问题、资料中无答案的问题、职责外问题；记录实际输出和是否按规则处理。普通单次资料问答不能单独替代创建助手项目。

第六周必须在外部自动化工具实际搭建“输入收集→分类→生成草稿→人工确认→写入系统”。项目要识别触发、变量、条件、必要的循环、字段映射、日志、重试边界和审核点；若流程无需循环，说明何时才需要。保存正常、缺字段、重复输入三种真实运行的结果。仅画流程图或阅读原则不算实际搭建。

延后复验使用第二任务的新材料；以主线独立运行实际日期为基准至少间隔 7 天。再次检查八项能力中本任务可观察的部分，并追问一处新变化。延后结果应与即时结果并列，不能覆盖原结果或隐藏退步。

## 7. 最少记录与维护验收

普通练习只保留资料、提供的任务说明、实际输出、自检状态和选填问题备注；日期自动记录。正式运行再记录关键核查、改动或未知处理及必要耗时。两类均不要求粘贴整段聊天、逐步截图或重复填写同一证据。

时间账区分可比较的人工原流程基线，与使用 Agent 的资料准备、操作、等待、核查、修改返工。零耗时应明确填 0；漏填不能当作 0。净省时为人工原流程总耗时减去 Agent 全过程总耗时，须在质量达到同一使用要求的前提下解释。

维护者每次改课须检查：默认三步是否仍可直接用示例开始、只填实际输出即可保存；保存时是否保留未确认的检查项；普通记录是否仍排除正式进度；正式目标是否有对应动作和反馈；提示是否逐步撤去；是否有新材料的独立任务；正常和异常材料是否仍可判；关键错误能否被识别；进度文案是否夸大学习证据。

使用 `node tests/beginner.test.cjs` 复查三步输入负担、自动合并复制、选填字段、检查未全勾时保存、草稿与快照隔离及正式进度排除。它验证实现合同，不替代真实的新手观察。

产品校验或自动化测试只能证明记录与规则的实现一致，不能证明课程有效。真实试学按 [试学与评估操作指南](pilot-guide.md) 执行；未开展前不填通过率、省时比例或提升结论。

## 8. 场景加练的内容要求（2026-11-21）

六门场景课按需选学，不改变原有周次、目标分母或能力等级判断。每门使用一项可交付成果串联方法与练习；默认仍为资料、执行、检查三步，只要求带回实际输出。扩展案例与正式项目验证沿用原有入口。

| 场景 | 需要观察的动作 | 关键错误 | 换材料的变化 |
| --- | --- | --- | --- |
| 长 PDF | 带着问题查版本和页码，说明读取范围 | 摘录冒充全文、旧日期、漏条件或猜回放期限 | 不同地区与版本；缺页；未明确取代的日期冲突 |
| 邮件 | 明确收件人的行动，核对时间、版本、附件状态 | 内部评审变开课承诺、声称已发送 | 换合作方与材料，迁移到内部消息 |
| 客户反馈 | 分别计算记录数、去重客户数，保留原话与多标签 | 重复客户当新人、把频次当根因或全体占比 | 缺编号；记录与汇总冲突；迁移员工反馈 |
| 汇报 | 围绕决定组织提纲，复算数字并保留样本限制 | 完成率与抽查率混用、回复者代表全体、编造省时 | 不同分母与资源需求，迁移到对外复盘 |
| Excel 清理 | 按规则预览与处理副本，保留原值和修改日志 | 丢前导零、空白补零、擅自去重或猜年份 | 不同行粒度与重复键；金额冲突；迁移库存表 |
| 文件命名 | 确认范围，展示旧新名映射，识别碰撞和缺字段 | 无授权执行、覆盖文件、用系统日期补业务日期 | 新目录与规则；目标占用；迁移跨目录归档 |

正常案例提供参考成果和两种纠错办法；辨错案例另换资料，包含可接受、需要修改和需补信息三类反馈。学前、人工基线、独立、迁移和延后材料互不相同。真实学习效果仍需按试学指南观察，不能由测试通过或保存记录推定。

可选文件样本与正常文字材料保持同一业务事实。PDF 保留物理页与正文页码区别；Excel 原表保留标识字符串、名称首尾空格、未知金额、零值和不完整日期；ZIP 只含虚构测试文档及说明/校验值，不含可执行脚本。实际操作练习先在副本或新目录确认范围与规则，再按原名映射、数量和内容核查。
