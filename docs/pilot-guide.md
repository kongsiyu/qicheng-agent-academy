# 真实试学与课程评估操作指南

设计基线：2026-11-17；默认交互于 2026-11-20 重构。真实试学尚未开展。本文约定如何收集和评审证据，不填写虚构的参与者、成绩、使用记录或省时结论。

## 1. 本轮要回答的问题

本轮首先确认目标学员能否完成主线学习、哪里需要帮助、能否独立识别关键错误、换材料后能否继续工作，以及包含核查返工后的投入是否值得。满意度作为体验信息单独记录，不代替能力表现。

使用 [课程质量设计与验收合同](course-quality-design.md) 中的八项能力、三档评分和关键错误标准。课程、项目、素材和评分规则需有同一版本记录，避免边教边改却混算成绩。

## 默认使用与正式试学的入口

公开产品默认进入 `#/project/start`；旧 `#/project/path` 也兼容进入新手三步。默认顺序是准备资料、让 Agent 帮忙、检查并保存，主要文本输入数为 0 / 1 / 0。示例与任务说明自动提供，复制时合并当前资料和要求；学员手动必填的主要文本仅为实际输出。自己的资料可替换，检查未勾齐仍可保存，问题或修改一句选填。

普通练习的 `kind: practice` 只允许 `support: guided`。轻量保存采用独立校验分支，确实不要求正式核查长文、八项评分或时间账，不是把必填表单藏入折叠区。它不计正式周项目、能力等级或延后复验，也不能用作独立后测成绩。

首次公开使用不强制前测、人工基线、八项评分和耗时。开展本指南的正式研究时，由主持人主动通过 `#/project/plan` 进入完整项目，安排 `pretest` 学前 Agent 尝试；人工原流程的时间比较另用 `baseline`。不能要求每位普通用户先完成研究记录才能开始课程。

如果参与者已完成三步示例、看过参考任务说明或接受教学帮助，再补做的任务不再是未经学习的前测。如实记录暴露经历，采用另一套新材料，并将缺少有效前测列为限制；不能把已保存的 `practice` 改称学前独立表现。

当前完整课程、进阶验证和旧数据保留。研究者不得为简化分析删除旧记录；按类型、版本、材料和提示情况筛选所需记录即可。

## 2. 参与者与试学组织

先组织一轮 5—8 位目标学员的小规模试学；这是发现问题的设计建议，不是有统计代表性的样本量。覆盖至少两种岗位，区分几乎未使用过 Agent 与已有基本使用经验的人；不要全部选择产品作者、技术人员或熟悉课程的同事。

正式开始前确认学员的设备、资料使用许可、可用 Agent 和每周实际时间。可用脱敏真实材料；使用教学材料须标明。主持人只收集评估所需片段，不要求提交客户信息、完整聊天历史或账户凭据。

每位参与者有匿名编号。研究者与学员约定哪些资料可保留、由谁可见、何时删除。课程学习记录和试学研究记录分开；导出的本地备份不是自动上传或同意参与研究。

推荐分两步：先观察其中 2—3 人使用默认三步完成一次普通练习，修正阻断性问题；再冻结版本开展完整主线试学。第一步重点观察能否不求助开始、复制任务、带回输出、对照资料和保存未完检查，不额外插入前测与八项评分。两步结果分别记账，版本变化后不得直接合并成同一通过率；已参与入门测试者的教学暴露须记录。

至少安排一名主持人和一名可独立复核的评分者。资源不足时，先缩小任务范围，仍应保留部分双人评分，不用模型评分替代校准。

## 3. 试学前准备清单

- 冻结课程版本、14 节主线与 3 节选修范围、任务包版本、评分表和通过条件。
- 确认正式参与者同意研究安排，由主持人主动进入完整项目；不要改写公开新手流程为强制前测。
- 准备前测 A、等难后测 B，以及第二任务的延后复验 C；测验答案和关键错误只给评分者。
- 为每套题准备源材料、预期关键事实、允许的未知回答、关键错误清单和可接受的替代输出。
- 预先写清主持人可说的话、求助分类、何时停止计时、外部工具故障如何记录。
- 试跑文件读取、记录保存与导出流程；确认没有把示例或草稿计为独立成果。
- 准备时间账、观察日志和问题清单；不以额外大量表单消耗课程时间。

等难性至少比较：资料长度与格式、关键事实数量、计算步骤、缺失与冲突类型、工具动作影响、输出复杂度。只替换人名但保留相同答案，不算新题；改变数值时重新计算标准答案。

前后测可在参与者之间交换 A、B 顺序，减少某一套题偏容易的影响。交换顺序不是随机对照试验，不能据此单独宣称课程造成了全部提升。

## 4. 测量时间点与执行

| 时间点 | 执行方式 | 保留什么 | 判断范围 |
| --- | --- | --- | --- |
| 前测 | 主持人主动从完整项目安排 `pretest`，在工具基础操作熟悉后、接触课程提示前，使用 A 或 B 的新材料尝试 | 输入、说明、实际输出；关键核查和求助能观察多少记多少；主持人按行为评分 | 确认先备能力，允许不会或留空，不把工具登录问题当成能力低 |
| 每周项目 | 按四周合同完成主线项目；记录正常、缺失、冲突、任务包交接和纠错 | 当周实际成果和最少关键证据 | 判断练习是否提供了目标能力的机会和反馈 |
| 即时后测 | 第四周用未见过的等难新材料完成主线独立任务，再做第二任务迁移 | 同前测，并保留迁移时调整的要求与原因 | 判断独立表现及即时迁移；不向学员展示参考答案 |
| 延后复验 | 主线独立运行实际日期至少 7 天后，在第二任务上使用新材料 C | 实际日期、资料、输出、核查、求助、耗时和评分 | 判断隔一段时间后的应用；单独呈现未完成者 |
| 选修 | 第五周外部助手，第六周外部自动化按各自合同执行 | 配置或可定位说明、实际测试输出、正常与异常结果 | 分别判断选修目标，不能只凭主线结课推定掌握 |

主线至少两次真实运行日期的跨度为至少 6 个自然日；延后复验与主线独立运行至少间隔 7 个自然日。这两个时间条件不同，均使用 Asia/Shanghai 实际日期。

前测、后测和延后复验允许使用常用 Agent、工作资料和学员自己的任务包；主测阶段不给课程预置任务说明、答案或针对当前错误的提示。工具使用是被评价能力的一部分，禁止一切 AI 不能测到本课程的目标。

前测尚未形成个人任务包是正常状态，不为补齐字段提前教学。普通使用中默认提供的课程模板属于提示，不能拿使用该模板完成的 `practice` 与正式独立后测直接等同。人工基线则按原有方式不用 Agent 完成，只服务耗时比较，不替代 Agent 能力前测。

不要只收最终成品。主持人针对一条关键结论追问依据，并加入一个小变化，例如替换资料版本、删除负责人、改变统计口径或调整写入对象。观察学员能否发现影响并修改结果。

若学员求助，先记录求助发生在哪一步，再按统一规则提供帮助。不要为了保住“独立通过率”拒绝合理帮助，也不要悄悄给提示后仍记为完全独立。

## 5. 主持人观察与提示规则

观察时请学员说出正在判断什么，但不要求持续口述每一步。主持人不演示鼠标路径或指出答案，除非进入已记录的帮助阶段。

| 分类 | 示例 | 如何记录 |
| --- | --- | --- |
| 操作环境问题 | 无法登录、文件打不开、Agent 服务不可用 | 记故障时间和恢复方式；单列环境影响，必要时重新安排 |
| 导航或表达问题 | 找不到下一步，不理解按钮或术语 | 记原话、停留位置、是否需主持人解释；作为产品问题 |
| 概念或策略问题 | 不知道何时应保留未知，开始前没检查资料 | 记错误与求助；具体提示后完成的相关能力最高为 1 |
| 执行或核查问题 | 来源不支持结论、比例算错、没有查看写入目标 | 记是否自行发现、依据、修改和复查；按关键错误规则评分 |

通用中性追问可用“你准备怎样检查这项结果？”；明确说“第二条价格用了旧版本”属于具体提示。两者都要记录，评分者根据帮助是否直接提供了判断来确定独立性。

先记录学员自然停住的位置和原话，再讨论原因。不要把“不会使用当前按钮”“缺少必要资料”“不懂业务口径”都归为“提示词写得不好”。

## 6. 双人评分与校准

正式评分前，两位评分者分别审阅同一组 3—5 份锚例，覆盖合格、提示后完成、证据不足和关键错误。对照合同解释分歧，形成一页补充判例。

小规模试学中，所有后测和延后复验尽量由两人独立评分；至少应双评所有疑似关键错误、临界结果，以及部分明显合格与不合格结果。记录实际双评数量，不把未双评的结果写成一致。

评分者先各自记录八项能力的 0/1/2、证据位置、提示和关键错误，再讨论分歧。不先给一个总分让另一人附和。条件允许时隐藏参与者姓名和前后测阶段，减少对进步的预期影响。

对关键错误是否存在、来源是否支持结论或行为是否独立出现分歧时，先回原材料与观察记录核实。无法核实时标记待核查，不默认通过，也不通过平均分消除分歧。

每项自评与人工评分并列保存。学员自评高于抽评，是需要帮助校准判断的证据；不以自评数量直接作能力通过人数。

本轮至少报告双评的一致项数/总项数、分歧类型、关键错误分歧和如何解决。小样本不必包装复杂统计系数，不能只写“评分可靠”。

## 7. 最少记录模板

默认三步普通用户不填写本节研究模板。主持人在正式研究中尽量复用已有输入、输出和观察记录，不把评分与统计劳动转嫁成新手必填框。

每位学员保留一行基本信息：匿名编号、岗位类别、先备经验、课程版本、外部工具与实际日期。不保留与评估无关的身份细节。

每次任务记录以下内容，已有项目字段可直接复用：任务与情境、资料位置或脱敏输入、个人任务说明、实际输出、一条关键核查证据、提示与修订、实际日期、完整时间账、八项评分和关键错误状态。

任务包交接单独记录使用者如何照着执行、卡住处、作者是否口头补充、一次实际修改及复用结果。不要求接手人写长篇体验报告。

问题清单至少包括：观察到的具体行为、影响哪项能力、出现次数/可观察人数、可能原因、拟修改处、复测方式与版本。把观察事实和原因推断分开。

## 8. 时间与效果指标

| 指标 | 计算或报告方式 | 避免的误读 |
| --- | --- | --- |
| 独立表现 | 逐能力列前测、后测、延后复验 0/1/2 及相应证据；给明确分母 | 理解题答对、勾选完成或满意不能代替独立行为 |
| 关键错误 | 按类型记录发生、是否自行发现、是否修复和最终仍存在的数量 | 正确文案与排版不能抵消来源、事实、计算或权限错误 |
| 求助与卡点 | 记录发生步骤、所需提示、实际人数和出现次数 | 完成得快可能来自主持人直接帮忙 |
| 新情境迁移 | 说明第二任务变化、学员调整与是否仍需提示 | 更换标题或复用相同答案不算迁移 |
| 真实使用 | 两次以上主线真实运行日期、跨度、质量检查及后续复用 | 学习天数或签到不能替代工作使用 |
| 完整成本 | 人工基线对比 Agent 的准备、操作、等待、核查、修改返工合计 | 模型生成速度或课程标称分钟数不等于净省时 |
| 完成与流失 | 同时报招募人数、开始人数、各阶段完成人数、原因及未知情况 | 只看结课者会隐藏学习负担和失败 |
| 体验 | 单独记录满意度、信心、主观价值与开放反馈 | 自信上升不证明事实核查能力上升 |

省时比较使用复杂度相近、达到相同使用质量要求的任务。净省时＝人工原流程总耗时－Agent 全过程总耗时；课程学习和研究评分的时间另列。质量不合格的任务不宣称已经获得可用的节省。

小样本优先给每人的完整记录和中位数、范围；同时说明工具、任务和先备经验。没有对照设计时，前后变化可描述为本轮观察，不能把全部变化归因于课程。

## 9. 如何决定修改和复测

若关键错误被现有验收方式误判为合格，先修正对应示范、练习、反馈或验收，再复测该类问题；不靠增加一段“注意准确性”的提醒关闭问题。

若多数人需要同一提示，检查是否缺少先备知识、材料读不全、任务跨度过大或界面难找；把修正落到一个明确位置，并使用新题复查。不能只改参考答案让旧题更容易通过。

若知识题通过而独立任务失败，优先补练习与反馈、撤去提示后的尝试和关键错误辨认；不默认需要更多课文。若独立表现合格但耗时无优势，检查任务选择、资料准备和复核负担。

真实试学结论允许为“证据不足”。先区分记录缺失、未参加后测、未达到独立水平和课程功能故障，再决定补测或改课；未完成者不能自动算掌握，也不随意归咎于学员。

## 10. 试学报告交付

报告至少包含：课程与工具版本、样本与经验分布、题目等难性说明、各阶段分母、逐能力表现、关键错误、求助、时间账、流失、评分分歧、修改项和下一轮验证安排。

每项效果结论附对应证据和局限。可写“本轮 6 人中 4 人在新材料上独立识别版本冲突”；只有真实记录支持时才填写该数字。尚未试学时写“待验证”，不要用演示数据替代真实结果。

上线前应确认基础内容、练习路径、数据保存、验收文案和关键错误处理可用。上线后的每轮课程更新仍需维护测试材料和抽评记录；产品自动化测试通过与课程学习效果分别报告。

本轮新增 `node tests/beginner.test.cjs` 检查默认三步、自动合并复制、轻量保存和正式进度排除。研究前仍要实际观察新手的理解与操作；测试通过、页面截图或教学示例都不能表述为真实试学通过。
