# 启程站内 Agent 陪练试点方案

首课用「把会议记录变成可信的待办清单」验证一件事。一个从未用过 Agent 的学员，能否在约 20 分钟内看懂示范、上手做一次、改掉一个错误，再用新材料自己完成任务。课程入口直接显示成品和「看 2 分钟演示」。

## 学员怎样上一节课

| 环节 | 学员做什么 | 网站和 Agent 做什么 |
| --- | --- | --- |
| 看演示 · 2 分钟 | 看三句会议发言怎样变成待办表，点「开始练习」 | 播放带字幕的录屏。下方有图文讲义，可回看表格的各列和「待确认」的用法 |
| 跟着做 · 5 分钟 | 补一句交付要求，点「让 Agent 整理」，把结果中的一条待办和原文对照 | 左侧显示带编号的会议记录，右侧依次显示指令、回答和当前要核对的一项。手机按材料、指令、回答的顺序呈现 |
| 改一次错 · 5 分钟 | 找出预置草稿里无依据的期限，编辑修改指令，让 Agent 重做，再核对差异 | 教练先问「哪一句支持这个日期？」学员卡住时给一级提示，继续卡住再指向原句。改对后换一条遗漏负责人的小题检查 |
| 换材料独立做 · 6–8 分钟 | 自己给站内 Agent 交代任务、检查结果、按需追问，提交成品和一处核对依据 | 显示新材料、交付目标和执行区。学员可随时请求教练帮助，获得具体提示的尝试记录为「提示后完成」，再给一组新材料复试 |

### 可直接写成首课脚本

- **开头 20 秒**。先放最终待办表，指给学员看事项、负责人、截止时间和来源四列。用一句话解释 Agent 是能按要求处理这份记录的助手，结果可以继续对话修改。
- **中间约 70 秒**。录屏用周会材料演示输入「整理成待办表，按发言编号注明依据，原文没说的写待确认」，运行一次。逐项对照 M01「12 月 3 日 17:00 前更新客户试用说明」和 M02「演示账号权限开通后再定日期」。
- **结尾约 30 秒**。展示把「陈宇周五完成账号检查」改成「陈宇检查演示账号，截止时间待确认，依赖测试权限」。停在练习入口，提示学员先核对一条再确认。同步提供讲义和可复制文字稿。

带练用现有周会材料。纠错用单独编写的固定错误稿，确保每个人都有机会练到同一个关键动作。返工时由模型根据学员的修改指令生成新结果。如果模型仍给出错误日期，教练引导学员对照后手动修正也可以完成该环节。

独立题换成活动筹备会。三条原文分别是「许宁 4 月 9 日 17:00 前发讲师确认单」「测试链接开通后由陈舟检查，期限还未定」「场地需在 4 月 10 日前确认，负责人待定」。学员提交三项待办和一条核对依据。准备一份等难度复试题，更换业务背景、人物和缺口所在行。

## 教练如何反馈和判断进度

同一个课页提供两个明确动作。**「让 Agent 执行」**根据学员指令生成或修订产物。**「给我一个提示」**针对当前步骤追问或提示。两者可复用同一模型，使用独立的系统提示和上下文。

教练每次只推进一个动作。先让学员指出证据，其次提示查哪一条，最后给一个示范。学员指出问题后，接着修改并核对。教练引用原文时，页面把材料编号链接到原句。缺少有效引用时，页面显示课程预设的核对提示。

独立提交按四项判断。学员提交后，站内 Agent 提供即时反馈和复练建议。试点由评审核对每份提交的指令、成品和修改记录。

1. 任务说明写清了要交付什么，并给出处理缺失信息的规则。
2. 待办覆盖原文中的行动，负责人和截止时间有依据。
3. 缺失的负责人或截止时间明确写「待确认」，依赖条件有保留。
4. 学员能指出至少一处原文依据，并能修正发现的错误。

四项均达到且没有使用针对该题的具体提示，记录为「本课独立完成」。有虚构负责人、日期或漏掉关键事项时，按对应问题给一题短练，再用新题复试。复试保留首次尝试的记录。七天后可以再做一份新材料来观察是否记得方法。

## 网站和服务怎么落地

- **课页**。新增一条站内教练试点入口。现有网站的材料、Markdown 预览、浏览器草稿和成果导出可复用。课程阶段、演示、题目、评分规则和可用提示由内容配置定义，程序决定当前阶段和通过条件。 [当前站点结构](../README.md#已实现的学习闭环)
- **模型接口**。GitHub Pages 托管静态前端。学员填写自己的 OpenAI 兼容接口地址和模型名，浏览器按课程环节把必要的材料和对话发给该接口。密钥默认保存在当前标签页。试点用同一批案例检查证据引用、错误纠正和响应耗时。
- **运行方式**。浏览器在学员发送消息后调用模型，并限制请求长度和等待时间。学员的练习文本保存在当前浏览器。超时后保留草稿并提供重试。录屏备一份图文讲义，模型不可用时仍可看课。
- **成本估算**。按每人 10 次模型调用、每次平均 1,500 输入和 400 输出 token 做预算。8 人跑完约 12 万输入和 3.2 万输出 token，另留调试和重试余量。具体费用按试点所选模型的实际单价结算。

## 实施顺序与试学指标

| 阶段 | 产出 | 工期估算 |
| --- | --- | --- |
| 备课 | 2 分钟录屏、图文讲义、带练材料、固定错误稿、两份等难度独立题和评分样例 | 1–2 个工作日 |
| 接入 | 一节课从讲解跑到独立提交，完成两种模型请求、草稿恢复、提示记录和错误重试 | 2–4 个工作日 |
| 试教 | 先观察 2 位零基础学员，修一次最常见卡点，再请 6 位零基础学员走完同一版 | 约 1–2 个工作日，取决于招募 |

上述估算按一节课、一名开发者使用现有站点计算。开发联调需要一个可由浏览器访问的模型接口。邀请试学前用手机和桌面各跑一遍，覆盖看演示、两次模型执行、提示后复试、刷新恢复，以及模型超时时保留草稿和重试。试学从通过邀请到第一次看到 Agent 回答，全程观察是否需要协助。独立题统一用同一个模型，记录首轮完成情况、具体提示、关键错误和总耗时。 [现有试学与评分方法](pilot-guide.md#5-主持人观察与提示规则)

扩课前的建议门槛是 6 位正式试学学员里至少 5 位无需操作指导跑出首个结果，至少 4 位在 25 分钟内独立完成新题并满足四条标准。若多人卡在第一次运行，先改界面或演示。若能跑出结果却仍接收编造的日期，先改核查和纠错练习，然后换一批题复跑。小样本结果用于判断这版课能否继续扩大试点。
