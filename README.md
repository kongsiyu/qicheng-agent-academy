# 启程 · Agent Academy

面向非技术岗位的 AI Agent 学习 Web 工具。课程与交互完全在浏览器执行；服务端仅需托管静态文件，无需数据库、账户服务或模型调用服务。

## 开始使用

仓库根目录就是可直接部署的网站目录。推送到 GitHub 后，可以在仓库 Settings → Pages 中选择 `Deploy from a branch`、`main` 分支和 `/ (root)` 目录启用 GitHub Pages。

Windows 下双击同目录的 `开始使用.cmd`，或在本目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 `http://localhost:8765`。建议固定使用同一个地址和端口，浏览器会按站点地址分别保存记录。

也可以将本目录的全部文件放到任意静态文件托管服务。入口是 `index.html`，页面使用 hash 路由，无需配置服务端页面重写。发布到 HTTPS 后支持离线缓存和添加到主屏幕。

直接打开 HTML 也能浏览，但浏览器对 `file:` 地址的本地存储支持不同，建议通过上面的本地静态服务或正式静态站点使用。

## 已实现的学习闭环

- **学习总览**：当前目标、下一课、课程与独立成果两条进度、能力积累。
- **学习路线**：4 周主线 14 节课程，加 2 周选修 3 节课程；共 17 节短课。理解检查与实际项目证据分别记录。
- **任务实验室**：会议待办、竞品简报、表格分析、产品资料问答、文稿初审、项目周报 6 个完整任务包。
- **项目学习**：选择一个主线任务反复练习，再迁移到第二项任务。每包包含带理由的示范、辨错反馈、逐步减少提示的练习和新材料复验。
- **学前与结课对照**：学前 Agent 尝试、人工流程时间基线分别记录；正常、缺失、冲突、独立、迁移及延后复验各自保存快照。教学材料与真实工作明确区分。
- **能力证据**：八项能力按练习记录展示自评；引导练习最高记为“提示后做到”。证据齐备供人工抽评，不宣称自动认证。
- **个人任务包**：编辑选题理由、资料清单、任务说明、验收表、异常处理与他人使用反馈，支持导出。
- **完整时间账**：记录准备、操作、阻塞等待、核查、返工、人工原流程及一次性投入；保留负收益。
- **边做边学**：示例资料、任务说明复制、四步引导、参考成果、验收清单、常见问题与进阶挑战。
- **独立练习**：在自己常用的 Agent 中执行，把结果带回验收；支持 TXT、MD、CSV 资料导入、草稿自动保存。
- **我的成果**：保存资料、实际输出和复盘；可导出单份 Markdown 作品。
- **目标与记录**：3 种目标、岗位方向、每周投入，完整 JSON 备份导出与严格校验后恢复。
- **离线使用**：首次通过 HTTPS 或 localhost 加载并完成缓存后，课程与本地练习可离线打开；外部 Agent 的运行依赖其自身网络。

## 进度规则

课程答对测验只记录为“理解检查通过”。重复通过不会重复计数，不据此认定能力掌握。

原有单次练习保留为“普通自检成果”，历史数据继续可用，不自动转成项目证据。新项目须记录任务说明、实际输出、核查、纠错与缺口/权限判断。修改关键内容会清除草稿验收勾选；存档快照不随草稿改变。发现存档有误可撤回自评，保留原文并从项目与能力进度排除。

学习计划进度为目标课程理解检查比例与每周项目证据齐备比例的平均值。starter 和 efficient 计 14 节主线课程与前四周项目；builder 计全部 17 节及六周项目。选修不影响四周目标分母。

第 1 周选题并完成正常案例；第 2 周主线正常/缺失/冲突三组案例；第 3 周形成六项任务包及他人使用反馈；第 4 周独立交付、第二任务迁移、完整真实工作时间账，以及至少两个实际工作日期覆盖七个日历日。教学案例不能满足真实使用跨度；覆盖一周不等于每日连续使用。结课独立记录七天后另做延后复验，不提前判完成。选修要求外部助手实测，以及自动化正常/缺字段/重复输入的实际运行记录。

验收表与能力等级均为学员自评。系统检查记录是否完整，不判断事实正确或替代教师抽评。选择“独立”不会自动改变提示情况；使用过课程或他人提示应如实记录。助手和自动化在外部获准使用的工具执行，站内填写不表示已创建助手或接通系统。示例为预置教学材料。

课程的质量设计、评分锚例与真实试学方案见 [课程质量设计](docs/course-quality-design.md) 和 [试学指南](docs/pilot-guide.md)。尚未开展真实用户试学，不提供虚构的学习成效数据。

## 客户端架构

| 文件 | 用途 |
| --- | --- |
| `index.html` | 应用入口与固定页面框架 |
| `content.js` | 课程、测验、任务包和目标静态数据 |
| `curriculum.js` | 八项能力、每周项目、示范理由、辨错和新材料案例 |
| `quality-core.js` | 多次练习、证据校验、项目门槛、延后复验和时间账纯函数 |
| `core.js` | 状态规范化、导入校验与进度计算；同时支持 Node 验证 |
| `app.js` | 路由、渲染、学习交互、本地存储与文件导入导出 |
| `project.js` / `project.css` | 项目学习、个人任务包与评审包导出界面 |
| `styles.css` / `details.css` | 桌面与手机布局、组件样式 |
| `sw.js` | 同源静态文件离线缓存 |
| `manifest.webmanifest` | Web 应用安装信息 |

没有运行时第三方依赖、远程字体、分析脚本或图片 CDN。无需 npm 安装或构建步骤。用户文本以转义后的文本形式呈现。

学习记录保存于当前站点浏览器的 localStorage，键名继续使用 `qicheng.agent-academy.v1`，数据结构升级为 schemaVersion 2。旧版记录和备份经严格校验后迁移，原课程与普通自检成果保留，新项目证据为空。新版备份包含项目草稿、快照、撤回、自评和任务包。每份学习证据最多 500 次存档且总量不超过 4 MiB UTF-8；完整备份导入上限 16 MiB。不同设备需用备份迁移，当前没有云同步。

## 内容维护与后续扩展

编辑 `content.js` 即可维护课程和任务。保留已发布内容的稳定 ID；字段结构见现有条目。新增主线内容时需同时维护目标中的 `targetLessons`。升级已发布数据结构时，应增加 schema 迁移逻辑。

第一版保留“复制任务说明 → 在常用 Agent 中执行 → 带回验收”的使用方式，以控制服务端和模型成本。后续如加入模型陪练，可独立添加可选接口层，并明确处理授权和密钥；现有课程、目标和进度不依赖它。

本轮已在浏览器验证示范、辨错反馈、减少提示、草稿刷新恢复、内容变更后清除验收、独立快照存档、撤回后进度回退、负收益显示、评审包导出及新版完整备份导出/恢复。手机尺寸检查无整页横向溢出；停止本地服务后，新增项目页面和记录仍可离线打开。验证输入均为标注的虚构界面测试材料，不是用户试学结果。

如已安装 Node.js，可运行以下检查：

```powershell
node tests/curriculum.test.cjs
node tests/core.test.cjs
node tests/quality.test.cjs
```

分别验证实际课程数据合同与课序、旧版迁移与进度分离，以及多材料、真实工作、撤回、迁移、延后复验、时间账与备份边界。
